O administrador pode conferir B no Table Editor/SQL Editor **do projeto

alterar tabelas. A consulta abaixo apresenta apenas rótulos e campos de segurança;
substituir os e-mails ilustrativos somente no painel, nunca no Git.

```sql
BEGIN READ ONLY;
WITH requested(label, email) AS (
  VALUES ('A', 'conta-a@example.invalid'), ('B', 'conta-b@example.invalid')
)
SELECT requested.label,
       u.id IS NOT NULL AS account_found,
       u.email_confirmed_at IS NOT NULL AS email_confirmed,
       coalesce(u.is_anonymous, false) AS anonymous,
       coalesce(p.protocol, 1) AS protocol,
       coalesce(p.academic_scope, 2) AS academic_scope,
       coalesce(t.allowed, false) AS test_allowed
FROM requested
LEFT JOIN auth.users u ON lower(u.email) = lower(requested.email)
LEFT JOIN public.noctua_sync_protocols p ON p.owner_id = u.id
LEFT JOIN public.noctua_academic_test_accounts t ON t.owner_id = u.id
ORDER BY requested.label;
ROLLBACK;
```

protocolo 2, escopo 5 e `test_allowed=true`. Esta consulta administrativa não é
prova de RLS nem reproduz a sessão Auth do ensaio. Ela tampouco reconstrói o
estado histórico de B na #25. Se algum campo divergir, preparar avaliação da
